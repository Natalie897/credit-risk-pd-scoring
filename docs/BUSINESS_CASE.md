# Учебный бизнес-кейс: PD для кредитных заявок

**Цель:** оценить вероятность условного события `default_12m=1` в течение 12 месяцев после даты заявки; проранжировать заявки по риску и проверить калибровку PD.

**Условный заказчик:** отдел продвинутой аналитики рисков. **Результат:** SQL-витрина, две сопоставленные ML-модели, отчет по метрикам и документация. **Не является** моделью банка или проектом оценки юридических лиц.

**Критерии готовности:** отсутствуют дубликаты `application_id`; train/validation/test разделены по времени; фичи доступны на момент заявки; метрики и графики воспроизводимы с фиксированным seed; при изменении кода проходят тесты.

**Горизонт метки:** 12 месяцев. Для вымышленных данных статус известен для всей имитируемой истории, включая конец 2025. В реальных данных нужна достаточная выдержка по времени: нельзя считать декабрьскую заявку 2025 полностью наблюдавшейся в ноябре 2026.

**Практические вопросы:** Как выбрать между качеством ранжирования и точностью вероятностей? Почему accuracy — слабая метрика при дисбалансе? Как не допустить target leakage? Как обновлять модель при изменении распределений?
